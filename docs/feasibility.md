# PharmacoWeave 规划可行性评估

评估对象是仓库内的《立项规划》v0.1（`docs/development-plan.md`）。评估日期 2026-10-29。结论用于约束首版架构。0.0.2 已按该评估实现第一种 NCA（单次静脉推注、连续采血）和一室静脉推注的对数线性拟合。0.0.3 补上加权非线性拟合、残差图和一份冻结的 NCA 参考。下文对其他设计的收窄仍然有效。

## 结论

规划作为独立定量药理学研究软件的立项基线**可行**。职责边界、实验实体、证据分级、文件交换优先、以及“适配成熟引擎而不是重写 NONMEM / PK-Sim”这几项应当保留。

规划第 8 节的完整目录如果同时做成可运行分析，则不可行。P0 同时交付任意试验设计的 NCA、一室和二室拟合、诊断图和可申报报告，超出了在科学上能够一次验收的范围。0.0.1 因此只落地**可安装、可校验、可复现的数据契约**。数值算法留在已经写明适用设计的接口后面。

## 评估时核对过的外部事实

- PyPI 上 `pharmacoweave`、`pharmafoundry`、`pharmaco-weave` 在 2026-10-29 返回 404。这只说明当时没有同名分发包，不是商标或域名结论。
- ICH M15 于 2026 年初到达 Step 4。FDA 于 2026-06-03 发布同名最终指南，说明 MIDD 证据的计划、模型评价、使用场景和报告方式。指南本身写明它不产生强制法律责任。
- ICH M10（2022）适合作为生物分析 LLOQ、ULOQ 和 QC 字段的设计参考。
- nlmixr2 与 Open Systems Pharmacology 的部分组件使用 copyleft 许可。它们只能在独立进程中适配，不能进入本包的 import 图。

## 应当保留的决定

1. 独立仓库、单一 Python 分发包。药理实验记录、NCA 和 PK/PD 验证与组学、治疗假设、电生理不是同一计算内核。
2. 预测的药物性质、实测浓度、模型估计和文献假设使用不同的 `evidence_type`：`observed`、`estimated`、`predicted`、`literature`、`hypothesis`。
3. 静脉给药报告 CL、V；生物利用度未知的血管外给药报告 CL/F、V/F。
4. BLQ、高于 ULOQ、缺失和无效观测不写入 `numeric_value`。0 不能充当 BLQ。
5. 跨项目个体对应关系进入 `identity_map`，并带有审核状态。相同的 `subject_id` 文本不是同一次实验的同一个体。
6. 交换格式是带版本的 JSON 清单加 Parquet 表。HTML 是阅读件。
7. 结果以新的 `run_id` 追加。拟合历史不被覆盖。
8. 软件标识为 research use。临床记录进入本包后仍然是研究用数据，不是申报包。

## 需要收窄的范围

### NCA 的第一刀只覆盖一种设计

终末斜率的选点、调整 R²、外推比例和梯形规则在 Phoenix、PKNCA 和各实验室 SOP 之间并不相同。稀疏采样、破坏性采样、稳态、尿药、多次给药叠加、输注和口服吸收相各自还有额外规则。

0.0.1 把第一份可执行配置锁为：

- 单次给药
- 静脉推注
- 同一个体连续采血
- AUC 方法 `linear_up_log_down`
- 终末相至少 3 点
- 报告 AUC∞ 时记录外推比例；默认 0.20 只作为报告旗标

配置能被加载和拒绝。上面三句描述的是 0.0.1：当时计算器尚未实现。0.0.2 起计算器存在，并对照事先冻结的参考输出，不把 PKNCA 或 Phoenix 引进依赖。当前 NCA 范围见 `docs/roadmap.md`。

### 房室模型先验证解析解

一室静脉推注有闭式解，适合作为参数回收的第一份基准。二室、口服一室、组合误差模型和 ODE 求解要等这份基准存在之后再进入。0.0.1 提供该闭式解，用于生成和核对合成浓度。0.0.2 用对数线性回归估计 CL 与 V。0.0.3 增加 `1/y` 和 `1/y^2` 加权非线性最小二乘，并把这一条模型的 `estimation_implemented` 设为 true。库里只放有测试方程的模型。写这段话时还没有二室条目；0.0.6 起已有二室静脉推注拟合。0.2.3 起恒速输注在解析解和 NCA 之外，也可以拟合 `CL` 与 `V`。

### 单位使用封闭词表

Pint 能解析任意单位字符串，也会接受与 PK 无关的单位。核心路径改为封闭词表：时间、药物质量、体重、体积、物质的量及其组合。`kg` 表示体重；药物质量用 pg、ng、µg/ug/mcg、mg、g。因此 `mg/kg` 不会变成无量纲，也不能直接换成 `mg`。质量浓度和摩尔浓度不自动互化，因为那一步需要分子量，必须单独写出来。

### 目录里的后期模块保持为预留包

`population_pk`、`pbpk`、`qsp` 可以导入，并带有阶段标记。导入不提供 NLME、PBPK 或 QSP 计算，对应的 `run_in_process` 会拒绝。0.0.4 把 `pd_models`、`pkpd`、`dmpk`、`toxicology` 从 reserved 改成 partial：只有有测试的直接效应 Emax、体外记录和毒理记录可以调用。间接反应和临床建议仍然不存在。截至 0.2.5，`simulation` 覆盖单次、等剂量重复和稳态解析暴露，并可接受调用方给出的对数参数相关；这不是群体后验。等剂量且等间隔的重复给药和已声明的稳态间隔也可以做 NCA。尿药排泄按记录体积单独计算，不进入血浆梯形积分。不等剂量、稀疏采样和破坏性采样仍然拒绝。

### 报告在分析运行之前只做数据清单

0.0.1 的 HTML 是校验清单：样本量、BLQ 计数、校验信息和明确缺席的分析产物。浓度–时间图、拟合优度图和 PK 分析报告在分析真正运行之后才生成。

### Schema 只有一个事实来源

Pydantic 模型导出 JSON Schema，CI 比对 `schemas/` 中的文件。手写第二套 Schema 会漂移。评估当时公开文件有五份：结果包、证据交换、研究、分析记录、NCA 配置。截至 0.2.5 有 14 份，仍由同一导出程序生成。

## 本次锁定的实现选择

| 项目 | 决定 |
|---|---|
| 包名 | `pharmacoweave` |
| 版本 | 评估锁定时为 0.0.1，pre-alpha。包版本现为 0.2.5 |
| 语言版本 | Python ≥ 3.11 |
| 许可 | MIT |
| 内存模型 | Pydantic v2，拒绝未知字段，记录不可变 |
| 表 | CSV、TSV、Parquet；绝对时间用带时区的 ISO-8601 字符串 |
| 数组层 | 不依赖 NumPy、SciPy、Pint、xarray。NCA 和拟合使用标准库数学 |
| 表格 | pandas DataFrame 作为观察值的平坦视图；Parquet 由 PyArrow 按列契约写出 |
| 报告 | Jinja2 HTML。PDF 延后 |
| 校验命令 | `pharmacoweave validate`。对象上的方法叫 `check`，以免覆盖 Pydantic 的 `BaseModel.validate` |

## 名称与外部引擎

工作名采用 **PharmacoWeave**。PharmaFoundry 不作为包名，以免和治疗发现平台的边界叠在一起。商标、域名和注册类别仍需法务审查；PyPI 名称当时空闲，不能代替这项审查。

外部群体模型和 PBPK 引擎不进入 import 图。截至 0.2.5，唯一内置可执行后端是 MIT 许可的 `pharmacoweave-analytical` 子进程，交换已经验收的解析曲线。`nlmixr2` 与 PK-Sim 出现在引擎目录里，许可证被记录，调用被拒绝。调用方自备的可执行文件可以在同时给出版本和许可证文本后单独启动，并记录文件哈希；这两个引擎仍不写入依赖。进程内群体模型、PBPK 和 QSP 仍然不计算。0.2.5 之后的分期写在 `docs/phase4-population-pbpk-qsp.md`：先做两阶段汇总、显式生理表和一条周转模型闭式解，全身动态模型和群体后验仍停在冻结参考之前。

## 科学验证现状

已经锁住的行为：

- 单位换算，包括 1 µg/mL = 1 mg/L、1 mL/min = 0.06 L/h。
- BLQ 行不能带数值；显式的 LLOQ/2 或 0 替换会留下审计列，且不改原始记录。
- 静脉参数不能标成 CL/F；口服参数在 F 未知时不能标成 CL。
- 终末相未合格时不能报告 λz、t½ 或 AUC∞。
- 采样相对时间必须和绝对时间之差一致。
- 定量值低于 LLOQ 时要求改标 BLQ。
- 合成静脉推注数据严格校验通过。24 h 为 BLQ。相同的 per-kg 参数给出相同浓度。
- 一室静脉推注解析解满足 C(0) = Dose/V，AUC∞ = Dose/CL。对 0.25 mg 与 0.05 L/h，AUC∞ = 5 µg·h/mL。

评估当时尚未开始、后来已经补上的验证：带噪声数据上的参数回收、不可辨识和优化失败，以及浓度–时间、残差和浓度–效应图。数值对照使用本包冻结的十进制参考，不导入 PKNCA 或 Phoenix。

截至 0.2.5 仍然没有开始的验证：

- 把本包结果对接到 PKNCA、Phoenix、NONMEM 或 PK-Sim 的外部数值比对。
- SEND 映射、21 CFR Part 11 和任何监管符合性测试。

## 和规划文本的对应

规划 Phase 0 的验收是：仓库可安装、CI 可运行、示例研究设计和 Schema 校验通过。该验收已在 0.0.1 完成。Phase 1 至 Phase 3 的已实现范围，以及 0.2.5 之后仍拒绝的功能，以 `docs/roadmap.md` 和 `docs/project-evaluation.md` 为准。上文对 2026-10-29 首版架构的收窄仍然有效：没有冻结参考的算法不进入公开函数，copyleft 引擎不进入 import 图。
